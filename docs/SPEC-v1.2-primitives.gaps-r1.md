MAJOR — new-actionable — Default `start=None` conflicts with the legacy fallback. `docs/SPEC-v1.2-primitives.md:184-185` says `start = e.get("start") if present else (...)`; `:209-212` says `boardkit.edge` gains `start=None, end=None` and **writes** these fields to its returned dict. A default call thus contains a present `start: null`, selecting `None` instead of `"none"` or the legacy `bidir` arrow. R6.3 would emit a reference to `ck-head-<tone>-None` (or otherwise mishandle the value). The existing factory returns a `bidir: true` edge without any `start` field (`vendor/boardkit.py:90-101`; reproduced on a scratch copy). Fix: specify that the factory only writes explicitly supplied, non-null head fields, and define null/unknown start handling consistently in both renderers. Test factory defaults and a `bidir: true` factory edge in both renderers.

2. MAJOR — new-actionable — The documented headerless split box cannot be made through the ops path as specified. R4 sets `head_h = 0` for an empty `text` (`docs/SPEC-v1.2-primitives.md:135-140`); the committed fixture has `splitrows.text == ""` (`docs/fixture-v1.2.json:124-144`). R8 tells lane C to call today's `box(...)` after accepting parts (`docs/SPEC-v1.2-primitives.md:238-245`), but the current writer calls `_require(p, "text")` before `box` (`store.py:248-257`, `:218-221`). Scratch-copy reproduction: `apply_ops(board, [{"op":"add_node","text":"","parts":["a"]}])` raises `ValueError: add_node: missing text`. Fix: explicitly permit empty node text when normalized `parts` is nonempty (while still requiring a text key or a deliberate default), and cover headerless split creation through `board_apply`.

3. MAJOR — new-actionable — Editing a split box can silently discard its part subtitles. R1 allows `{text, sub}`, and R4 promises to draw the per-part `sub` (`docs/SPEC-v1.2-primitives.md:52-54`, `:142-144`); the fixture exercises this (`docs/fixture-v1.2.json:132-136`). But R7 directs the textarea handler to replace *all* parts with `{text: line}` objects (`docs/SPEC-v1.2-primitives.md:225`, `:230-234`), so changing any part text discards every `sub`. R8's normalization phrasing `[{"text": …}]` (`:241-243`) also leaves preservation of submitted object `sub` unclear. Fix: specify a lossless edit representation or a line-edit merge preserving each unchanged part's metadata, and explicitly preserve `sub` on dict entries in ops; add a fixture round-trip test that edits part text and checks remaining subtitles.

4. MAJOR — new-actionable — The promised parity/selftest gate is not wired into a required executable gate. R0 assigns `tests/test_editor.py` to the orchestrator and R0 says it normalizes differences (`docs/SPEC-v1.2-primitives.md:16-18`, `:30-32`), but R9 lists the existing suites, lane A's render suite, and lane B's selftest (`:271-292`); it never names a command or acceptance assertions for the cross-renderer test. The current `tests/test_editor.py` does not exist (expected before implementation), and `.github/workflows/tests.yml` invokes only the old Python suites and pane smoke. Thus all listed gates could pass with diverged static/JS shape structure or missing new editor behavior. Fix: make the orchestrator own the CI change as well as the test, require its local and CI invocation after merge/sync, and state that it compares fixture SVG elements/order/attributes and checks the `shapes`/`heads`/`grid` selftest steps for truth rather than mere presence. Include negative cases for snap-off and legacy heads.

5. MINOR — new-actionable — The lane-B reproduction recipe cannot import its renderer as written. R9's example begins `import sys, boardkit    # sys.path.insert(0, "vendor")` (`docs/SPEC-v1.2-primitives.md:280-285`), but `boardkit.py` resides under `vendor/` and the purported path insertion is a comment *after* the import. Scratch-copy execution from the repository root returns `ModuleNotFoundError: No module named 'boardkit'`. Fix: put `sys.path.insert(0, "vendor")` before `import boardkit`, make the here-document executable rather than commented pseudocode, and use a scratch output path.

6. MINOR — new-actionable — Empty `parts` changes a pill's shape in one reading of R4. R4 says `parts` applies to `box` and `pill`, but if normalization leaves none it says "draw a plain box" (`docs/SPEC-v1.2-primitives.md:133-136`); R2 says `pill` is unchanged (`:73`). A pill with `parts: []` therefore either becomes a rectangle or retains its pill outline depending on lane interpretation. Fix: say "render the node normally for its kind, without split content" and test a pill with empty parts.
